## What the feature is

A sell-side lead magnet. A seller comes to `/instant-offer/`, chooses Instant Offer or Consign, identifies their watch, uploads photos, leaves contact details, and (for Instant Offer) sees a real number on screen: the median dealer asking price for that exact reference over the last 45 days, nudged for condition and set, less 15%. The number is "subject to authentication" and holds 48 hours. Consign requests get a confirmation and a market read instead of a number.

The design reference is the WristCheck sell flow (wristcheck.com/sell). Henry sent screenshots of it and said "this should be the flow and what it should look like". The structure is copied; the skin is DBH's. Two options, not three (no "list online").

Henry's original ask was "photo matching for accuracy". That exists: the seller's photos are read by a vision model and checked against the dealer index. Details below.

Objects this feature added, all via Supabase migrations (names `instant_offer_*`):

| Object | Purpose |
|---|---|
| `wholesale.instant_offer(p_reference, p_dial, p_days=45)` | Market stats from `wholesale.listings` (FOR_SALE, classified, price>500, last N days). Dial-aware when ≥5 listings match the dial. Returns n, n_ref, median, p10, p90, low, high, brand, model, last_seen. |
| `wholesale.ref_profile(p_reference, p_days)` | What the index says a reference looks like: modal brand/model/metal/dial/bracelet/bezel plus `dial_share`, `metal_share`. Used to flag photo/reference conflicts. |
| `wholesale.photo_candidates(brand, model, dial, metal, bracelet, bezel, days, limit)` | Given a photo read, the references in the index that look like it, with counts and medians. |
| `wholesale.ref_search(q, limit, days)` + `wholesale.ref_base(r)` | Typeahead. Matches reference prefix or brand/model/nickname words; folds Rolex dial-code suffixes (`126500LN-0001`) into the base reference; attaches a catalog cutout image from `public.pieces` when DBH has one. |
| `public.dbh_offers` | One row per submission. RLS enabled, zero policies: service role only. Columns cover the watch, answers, photos (storage paths), market snapshot, offer, photo read/match, contact, option, ip/ua. |
| Storage bucket `dbh-offers` (private) | Seller photos, at `pending/<session>/<ts>-<name>`. Signed upload URLs from the API; signed read URLs for the vision call. |
| Index `listings_ref_core_forsale_idx` | Partial expression index so the stats function is fast. |

Existing things it relies on: `wholesale.ref_core(text)` (uppercase alnum only), `wholesale.norm_dial(text)`, `wholesale.listings` (the live dealer-group index, ~65k priced listings per 30 days, ~2,000 references with ≥3 recent listings), `public.pieces` (DBH's own catalog with public cutout images in bucket `pieces`), `check_rate_limit` RPC.

Known data noise: the classifier's `model` and `case_material` fields are imperfect (a 126334 Datejust is sometimes labelled "Daytona"; a rose gold 228235 can carry `YELLOW_GOLD`). Do not "fix" this by editing listings. The UI copes by letting the seller pick from a short list.

## API contract (`POST /api/submit-form`, JSON, `action: "instant-offer"`)

| `op` | In | Out |
|---|---|---|
| `search` | `q` | `results[]`: `{ref_core, reference, brand, model, n, median, dials[], metal, size_mm, image}` |
| `quote` | `reference, dial?, condition?, set?` | `{ok, amount, low, high, confidence, show_range, needs_review, margin_pct, adjustments, expires_at, market}` or `{ok:false, reason:"thin", market}` |
| `sign-upload` | `filename, mime, session` | `{path, uploadUrl}`; client `PUT`s the file to `uploadUrl` |
| `photo-read` | `photos[] (paths), reference?` | `{status, read, model, conflicts[], candidates[], suggested_reference, profile}` |
| `submit` | everything (see `lib/instant-offer.js`) | inserts `dbh_offers`, emails Henry via Resend, returns the same shape as `quote` plus `id` |

Pricing rules (in `priceIt`): `MARGIN` env `INSTANT_OFFER_MARGIN` default 0.15; condition nudges `unworn +2%, excellent 0, good -4%, fair -10%, poor -18%`; set nudges `full 0, box -3%, papers -3%, naked -6%`; fewer than 3 listings means no number; confidence HIGH (≥20 listings and dial matched or tight band), MEDIUM, MEDIUM_WIDE (shows a range), LOW; amounts ≥ $75,000 flag `needs_review`; offer valid 48h.

Photo read (in `readPhotos`): up to 3 photos, model `google/gemini-2.5-flash-lite` via OpenRouter (env `OPENROUTER_API_KEY`, ~$0.001 per read, ~4s), same prompt vocabulary the pipeline uses on dealer photos (STEEL / YELLOW_GOLD / PRESIDENT / FLUTED...). Statuses: `match`, `mismatch` (reference visible in photos), `consistent`, `mismatch_attributes` (typed reference vs `ref_profile`, only flagged when `dial_share`/`metal_share` ≥ 0.7 so multi-dial references are not flagged), `candidates` (nothing typed), `read`, `unreadable`, `not_a_watch`, `error`. On `submit` the photos are re-read server-side and stored; mismatches set `needs_review`.

## Client flow (the inline script)

1. Option cards: tabs, "Get started" sets the radio and scrolls to `#sell`.
2. Step 1: option radio, location select, typeahead (`op:search`, 220ms debounce; pick fills `chosen`; multiple dials show chips; "enter manually" reveals brand/reference/dial inputs), Yes/No radios (box, papers, worn, polished), notes, acknowledgement. Validation in `validate1`.
3. Step 2: six-slot photo guide (inline SVG line drawings), tips, drag-drop, thumbnails, then `op:photo-read` runs automatically after uploads settle and renders the strip under the thumbnails (match / conflict with candidate buttons / candidates / read). At least 3 photos and a reference are required to proceed.
4. Step 3: first/last name, email, phone (+1 shown), two checkboxes, submit. Condition is derived: not worn → `unworn`, polished → `good`, else `excellent`. Set is derived from box/papers.
5. Result panel (black): the number, dealer median, listing count, offer band, note, held-until; or the thin-data state; or the consignment confirmation with a market read.
6. Deep link `/instant-offer/?ref=126500LN&dial=black` preselects the watch.
